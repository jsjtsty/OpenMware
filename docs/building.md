# Building

Everything third-party is fetched as source by CMake and compiled with the project (no package manager):

| Library | How | Trimmed to |
| --- | --- | --- |
| SDL3 3.4.18 | FetchContent, static (shared `libSDL3.so` on Android) | no joystick/haptic/camera/sensor/tray/dialog/renderer/OpenGL, no tests/examples/install |
| zstd 1.5.7 | FetchContent, static | decompressor only |
| libwebp 1.6.0 | FetchContent, static | decoder only, no utilities |
| stb | FetchContent, headers | image, truetype, vorbis |
| FFmpeg n9.0.2 | ExternalProject (configure + make), **shared** (LGPL; `-DOMW_FFMPEG_SHARED=OFF` for a private static build), see [third-party.md](third-party.md) | ASF demuxer, WMV3/VC-1 and WMA2/WMA Pro decoders, swscale, swresample |

Versions and SHA-256 hashes are in `cmake/Dependencies.cmake` and `cmake/FFmpeg.cmake`. The first configure needs network access.

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

## Per platform

* **Windows (MSVC)**: FFmpeg is configured by its own `configure` script, which needs a POSIX shell: install MSYS2 (`pacman -S make diffutils nasm`), rename `usr\bin\link.exe` away so MSVC's linker wins, and run CMake from a VS developer prompt. `OMW_MSYS2_ROOT` overrides `C:\msys64`. Shortcut for experiments: `-DOMW_FFMPEG_ROOT=<prefix>` uses an existing FFmpeg instead (DLLs next to it are copied).
* **Linux**: needs the usual SDL3 development packages (X11/Wayland, ALSA/Pulse, ...), `make`, and `nasm` for the fast paths (optional).
* **macOS / iOS / Android**: use the scripts, they build the engine and the native launcher app around it: `scripts/apple/build.sh macos|ios` and `scripts/android/build.sh debug|release`. See [launchers.md](launchers.md).

The CI workflow `.github/workflows/build.yml` runs exactly these commands.

## Shaders

The 2D shaders are HLSL (`shaders/hlsl`). They are compiled once with SDL_shadercross into the three formats SDL_GPU backends take and the results are committed: `shaders/prebuilt/{spv,dxil,msl}`. A build copies the sets its platform needs to `<build>/shaders` (Windows: spv + dxil, Linux/Android: spv, Apple: msl; override with `-DOMW_SHADER_FORMATS=all`).

After changing HLSL, rebuild the sets with a `shadercross` executable on PATH (or `-DOMW_SHADERCROSS=<exe>`):

```bash
cmake -S . -B build -DOMW_REGEN_SHADERS=ON
cmake --build build --target omw_shaders_regen
```

The `msl` files are Metal *source*. On Apple hosts the build compiles them with Xcode's `metal`/`metallib` into `.metallib` libraries for the target SDK (macOS or iOS), which the engine prefers; if the Metal compiler is missing (Xcode 26: `xcodebuild -downloadComponent MetalToolchain`), the MSL source is shipped and compiled by the driver at load time.

Only the Direct3D 12 (DXIL) set has been run on real hardware so far; the Vulkan and Metal sets are generated by the same tool but untested.
